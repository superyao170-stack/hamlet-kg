# v0.6 实验进度与问题记录

记录更新：2026-10-11（上海时间）；本轮最终复核于该日完成。本页区分工程验证与可用于论文的方法证据，所有当前检测结果均不构成正式主实验。

## 1. 本轮完成的工程能力

- 对完整 CSV 严格逐行校验、保留来源行号、建立 SQLite 时间索引，标签独立保存。
- 由无标签流构造冻结因果缓存，交易到达特征保存一次，事件保存成员引用；按完整时间组切分。
- 各模型/种子共用缓存，神经模型按批训练，训练范围拟合 scaler 和权重；树模型使用只读训练磁盘矩阵。
- 分数落盘后计算同口径 AP、验证阈值和每日预算，导出全部预测；不以事件是否命中筛选候选。
- 恢复时核对模型、策略、输入定义和训练阶段冻结的验证阈值；失败/中断不写成完成实验。
- 保留首轮失败结果，针对短训练时段的周期标准化风险增加可选固定周期缩放；不读取未来统计或标签。

版本 v0.5 曾完成264项测试；v0.6 含周期修正的最终完整检查 **362项通过、无跳过**，标准库环境275项通过、87项跳过。实际恢复记录见本页后续条目及本机 `outputs/v06_verification.json`。

实验命令不调用 LLM。使用的检测策略来自此前真实 DeepSeek 编译结果，训练前已冻结，本轮没有产生新 API 调用。代码和依赖版本分别见根 README 与 `requirements-benchmark-lock.txt`；本机 LightGBM 为没有 OpenMP 的单线程构建。

## 3. 原始文件前缀的问题

先按预定20k、50k、100k原始行前缀诊断，没有根据模型结果或标签挑选行：

| 原始前缀行数 | 总正例 | 时间范围 | 训练/验证/测试正例 |
|---:|---:|---|---|
| 20,000 | 1 | 首日00:00–00:29 | 0 / 1 / 0 |
| 50,000 | 2 | 首日00:00–00:29 | 1 / 1 / 0 |
| 100,000 | 5 | 首日00:00–00:29 | 3 / 2 / 0 |

划分约60%/20%/20%，完整相同时间戳组保持在同一区间。这些前缀不是整个公开数据的时间或类别代表样本；后续原始行还可能包含相同时段的交易，所以前缀上下文也不完整。

20k训练段没有正例，程序拒绝训练。50k训练和验证各一个正例，可以验证优化、输出与恢复接口，但测试没有正例，AP、Recall和F1均无定义。程序用 `null` 表示，汇总记录 `n=0, n_missing=3`，没有将它们补成零或伪造检出结果。

v0.5 另外预先定义最早连续6小时窗口，检查发现511,357笔，超过当时250k资源上限，未进行训练。v0.6 磁盘缓存解决这一工程限制后继续使用原窗口，纳入全文件该时段所有源行，没有根据测试效果移动窗口。该窗口如今已经用于探索，后续方法选择不能再把它当作未见的最终测试。

### 4.4 数值失败诊断与周期缩放修正

按无标签特征检查，首轮神经模型的训练时间覆盖过窄，`hour_cos`训练均值约0.99775、标准差约0.00207；验证平均绝对Z-score约43，测试约297、最大约480。seed13的base测试最大分数仅约1.09×10⁻¹⁸，seed42的event仅约1.28×10⁻¹³；另有模型饱和到1。这是实际数值与分布问题，不能把阈值微调当作解决。

新增可选 `--neural-scaling fixed_periodic`：将数学上本就位于[-1,1]的 `hour_sin/hour_cos`保留原范围（mean0/scale1），其他特征仍只按训练段拟合。所有神经配置及历史成员采用相同处理，策略随模型保存；旧checkpoint与默认standard保持兼容。不改缓存、标签、时间窗、切分、种子或已有结果。

修正后的同窗口重跑属于探索性数值诊断。本轮只缓解数值饱和，并未证明事件表示的收益；后续主实验需预先固定预处理、训练/验证计划，保留尚未用来迭代的时间段。



修正重跑已完成，目录 `outputs/ibm-hi-small-v8-first6h-fixed-periodic-v06/`：三个种子、base/flat/event三种神经配置，共9个模型。除周期缩放外，缓存、完整时间组划分、策略、种子、批次、打乱缓冲、学习率和轮数与4.3相同。原树模型未重复训练，原版15模型输出保留。

| 神经配置 | 原standard测试AP均值 ± 样本标准差 | fixed_periodic测试AP均值 ± 样本标准差 |
|---|---:|---:|
| base | 0.00035182 ± 0.00005313 | 0.00072242 ± 0.00008726 |
| flat | 0.00030248 ± 0.00001103 | 0.00081860 ± 0.00015348 |
| event | 0.00075270 ± 0.00032376 | 0.00060559 ± 0.00004992 |

九个修正模型的全部测试分数均未精确饱和到0或1，原先整体趋零的问题得到缓解，但并未解决检出能力：事件模型AP低于base和flat，所有配置在0.1%调查预算下仍无检出。固定验证阈值下，event的三个种子分别检出3/2/1个正例，同时误报4743/2136/792笔；flat均检出6个正例，但误报4510/3497/3176笔。固定阈值和固定预算是不同政策，不能把大量误报换来的召回当作低预算收益。

这一对照说明数值稳定和结构表示有效性是两个问题。目前结果更支持继续检验成员聚合的必要性，而不是宣称知识图谱编码优于摘要；保留负结果并优先扩充训练时间覆盖、冻结强基线比较。修正版进程峰值RSS约309MiB，但只含三种神经配置，不能与原含树模型的607MiB直接作效率优势比较。

修正版seed42的event恢复全部102,438笔，分数、原始行号、其他预测字段与告警和保存前一致，最大绝对分数差0；阈值保持训练时验证段的0.537401556968689。记录在修正版目录 `restore_verification.json`。无标签缩放诊断位于 `outputs/ibm-hi-small-v8-first6h-diagnostics-v06/scaling_audit.json`，不读取评价标签：当前样本事件覆盖由训练2.43%升至验证10.57%、测试16.04%，提示空历史起点和时间分布变化也需要研究。

## 5. 下一阶段的实施顺序

1. 周期修正及恢复核验已完成；接下来在训练/验证范围分析事件覆盖、冷启动、类别权重与误报，检验成员聚合相对摘要的必要性；不通过挑测试阈值弥补模型问题。

4. 集成GFP + LightGBM与Multi-GNN，在相同可见历史和候选上重跑；当前树模型不代替它们。
5. 在未用于反复迭代的时间区间与LI配置上验证，完成匹配随机删除、误报及规模实验。

当前优先级是完整数据实验可运行、比较可信和表示机制可检验。接口报告与图谱展示已经具备，继续增加语言模块不能解决这些研究缺口。
