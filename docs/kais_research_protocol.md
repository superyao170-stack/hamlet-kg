# 面向 KAIS 的反洗钱结构感知检测研究协议

版本更新：2026-10-11，代码 v0.6。本文是后续实验与写作的约束文件，不是已经完成的研究结论。

目标是在公开数据上研究交易级洗钱风险检测：对每一笔到达的交易，利用当时可见的历史记录给出风险分数，并提供可回查原始交易的行为证据。论文主线是**时间因果约束下的行为事件表示、结构感知检测与证据忠实性**。平台接口、图谱可视化、检索和语言报告用于支持复现及审计，不单独充当方法贡献。

当前检测模块是研究原型。小型演示数据、单元测试通过和一轮训练输出，只能证明软件链路能够执行，不能证明对真实银行业务有效，也不能证明新颖性或达到投稿条件。GFP 加 LightGBM、Multi-GNN 等外部强基线目前尚未集成，必须在论文定稿前完成。

v0.5 已增加原生 LightGBM 基础特征/事件摘要对照、数据质量审计及固定划分多随机种子运行。它们为公平实验提供可复现的工具，不等同于 GFP 复现，也不自动证明事件方法优于强基线。

v0.6 增加严格流式数据准备、磁盘时间索引、因果样本缓存、按批训练与磁盘评价。完整 HI-Small 的5,078,345笔已完成严格读取与索引，最早六小时511,357笔已完成原版15模型和周期修正9模型的先导比较；这不等于完成全时间范围主实验。先导训练/验证/测试正例仅15/33/27，结果用于发现问题，不能作为最终测试反复筛选模型。 修正缓解周期特征造成的分数饱和，但事件模型仍低于基础/摘要模型，不能据此支持结构优势；下一步以更充分的训练覆盖和未用于迭代的评价区间检验。

## 1. 投稿定位与研究连接

### 1.1 为什么优先按 KAIS 的问题组织论文

Knowledge and Information Systems（KAIS）的官方范围包含知识与数据工程、决策支持、动态系统、时空数据处理、学习与适应，以及知识发现与数据挖掘。交易记录到行为事件的知识表示、时间约束下的检测和可审计证据，与这些方向有实际连接。适合程度仍取决于最终方法与实验证据，不能由项目名称或期刊范围直接推导录用。参见 [KAIS 官方范围](https://link.springer.com/journal/10115/aims-and-scope) 和 [作者指南](https://link.springer.com/journal/10115/submission-guidelines)。

CCF 于 2026-03-31 发布第七版推荐目录，并于 2026-04-09发布勘误公告；官方目录中 KAIS 列于数据库、数据挖掘与内容检索领域 B 类。选刊以学校采用的目录和认定办法为准。期刊影响因子与 CCF 等级是不同评价，不能互相替代。参见 [CCF 第七版发布公告](https://www.ccf.org.cn/Academic_Evaluation/By_category/2026-03-31/870181.shtml)、[官方目录与勘误入口](https://www.ccf.org.cn/Academic_Evaluation/By_category/) 和 [官方 PDF，第 33 页](https://www.ccf.org.cn/ccf/contentcore/resource/download?ID=112CF3BF7E1140ACEB271ADAED12A67ADFABB8FF099E40C2759502A85C8A281F)。

投稿前应回答的核心问题不是“能否把若干组件组合成系统”，而是：**在相同信息、相同候选交易和相同评估协议下，行为事件表示带来了什么可验证的增益，何时有效，何时失效？**

### 1.2 与丁家昕公开研究方向的连接

上海交通大学官方页面的中文姓名为“丁家昕”（Jiaxin Ding）。其个人主页列出 Structure-aware Learning 等研究方向，并列有 ICML 2025 的 TopInG。可以把研究联系落实为“结构表达是否改善识别、解释是否忠实于模型、模型是否依赖伪相关”三个问题。参见 [上海交大教师页面](https://www.cs.sjtu.edu.cn/jiaoshiml/dingjiaxin.html) 和 [个人主页](https://jhc.sjtu.edu.cn/~jiaxinding/)。

TopInG 研究通过持久同调与 rationale filtration 学习解释子结构，其理论结论具有相应条件。当前 HAMLET-KG 没有实现持久同调、TopInG 的过滤学习与损失函数，也没有继承其理论保证。这里借鉴的是结构与解释一起接受验证的研究问题，不能把引用该论文写成复现了 TopInG。参见 [TopInG 原始论文，PMLR 2025](https://proceedings.mlr.press/v267/xin25b.html)。

这些公开方向可以帮助组织研究陈述，也有助于展示继续研究的能力；它们不代表已有合作、导师认可、博士录取或论文录用保证。若以后联系老师，应展示可复现的方法问题、强基线结果与失败分析，而不是只展示集成平台截图。

## 2. 任务定义与允许使用的信息

### 2.1 预测对象

主任务为交易级二分类。对交易 x_i，模型输出 s_i ∈ [0,1]，对应公开数据中的交易级洗钱标签 y_i ∈ {0,1}。输出应称为“模型风险分数”或“可疑交易告警”。当前 sigmoid 输出未经概率校准，不能称为已校准的洗钱概率；标签预测也不等同于法律意义上的洗钱认定。

每笔合格交易均属于评估候选集。即使交易没有匹配到任何行为事件，也必须得到分数；不能先用规则筛出“看起来可疑”的交易，再只在这些候选上计算指标。无事件样本使用基础交易表示和空事件汇总。存在缺失标签或无法解析字段的记录时，要公布排除原因、数量和正负类别变化，不能静默过滤。

当前 `build_samples` 只对 `TRANSFER` 原子事件生成检测样本。若数据适配器把其他支付方式映射为 `TRANSFER`，要公布映射规则；论文不得把这个任务口径扩写为已经覆盖所有银行业务类型。

### 2.2 严格的可见历史

在交易 x_i 的时间 t_i，允许输入为：

- 交易本身在到达时可见的金额、币种、付款方、收款方等字段；
- 时间严格早于 t_i 的历史交易，以及由这些历史构造的统计量；
- 由历史交易与当前交易形成的行为事件。

禁止输入未来交易、当前或历史交易的洗钱标签、注入模式 ID、事后调查结果、标签驱动的事件类型，以及从完整数据图中预先计算的未来度数或未来邻居。账户 ID、交易 ID 和来源行号可以用于关联、排序和证据回查，但不能直接作为数值特征或可训练身份嵌入加入当前模型。

当前实现把相同时间戳的交易视为同时到达：先用严格更早的历史为整组交易构造样本，之后才把这一组加入历史。组内交易互相不可见。按 ID 排序只保证结果确定，不赋予同一时间戳内部真实先后关系。时间戳精度越粗，这一策略越保守，应报告每个数据集的同时间戳比例。

“严格因果”在本文中指信息时间顺序正确，不意味着已经识别了洗钱行为的现实因果机制。删除交易的解释实验也只评价模型对输入变化的依赖。

### 2.3 历史状态与模型参数分开处理

测试时可以观察测试区间内已经到达的无标签交易，并更新历史状态，这是预先定义的流式观测政策。测试标签始终只用于评估，不能更新模型参数、阈值、归一化统计或规则参数。验证区间的交易可以成为随后测试交易的可见历史，但验证标签只用于模型选择和阈值选择。

跨数据集推断时要明确历史从空状态启动，还是提供一段无标签预热前缀。两个政策不能混在同一结果行；如使用预热，要公布时长、候选样本计数与标签使用政策。

## 3. 当前实现与待验证贡献

### 3.1 当前链路

```text
CSV / CaseGraph
    → 无标签交易字段与独立评估标签
    → 按时间分组回放
    → 基础统计 + 有界历史行为事件
    → 训练区间拟合表示与分类器
    → 验证区间选择阈值
    → 测试交易全量打分
    → AP / 固定阈值指标 / UTC 每日预算指标
    → 删除源交易后重建历史的证据审计
```

`stream.py` 负责因果样本构建，`policy.py` 验证固定算子的规则结构，`neural.py` 提供可选 PyTorch 检测模型，`metrics.py` 实现评价口径，`evidence.py` 执行源交易删除与证据回查，`runner.py` 保存运行清单、模型和结果。CLI 的 `detect-demo`、`detect-train`、`detect-score` 分别用于链路演示、训练评价和冻结模型打分；具体参数以各命令 `--help` 为准。

大文件使用 `prepare-data → cache-data → detect-cached-benchmark → detect-cache-score`：`dataset.py` 保留原始行号及独立标签，`cache.py` 回放无标签交易流并冻结到达特征与成员引用，`disk_runner.py` 按批训练和评分，`disk_metrics.py` 在磁盘分数上使用相同 AP、阈值和预算口径。这条路径的告警只附候选事件数量与可选来源行号，明确标记未审计；不自动执行上面的删除审计步骤，也不生成 LLM 报告。

PyTorch 属于可选依赖。它的存在不意味着当前模型依赖完整图学习框架，也不意味着原项目的知识检索模块已经完成反洗钱检测验证。旧的模式匹配、案例检索和 LLM 规则编译可作为辅助流程，不能把检索命中率作为交易检测准确率。

### 3.2 已实现能力及其边界

| 组件 | 当前实现 | 不能据此声称 |
| --- | --- | --- |
| 交易基础表示 | 金额、币种一致性、小时周期、账户历史收付与对手方统计等 | 已利用完整窗口的所有历史；当前每个历史桶还有数量上限 |
| 行为事件 | `fan_in`、`fan_out`、`pass_through`、`relay` 四类局部事件 | 已完整覆盖环路、散入散出、所有分层清洗方式 |
| 事件成员 | 原始交易表示、事件内角色、相对时间 | 成员具有洗钱真值解释标签 |
| 有界历史 | 每个账户、币种、方向的历史队列受时间窗和数量限制 | 全系统恒定内存，或百万交易生产服务已就绪 |
| 事件编码 | 成员表示池化、事件类型与描述量、事件门控汇总 | 完整全局异构 GNN、多跳全图消息传播、TopInG |
| 解释 | 固定模型下删除源交易并重建可见前缀，附随机控制 | 已证明现实因果、最小充分证据或内在可解释性 |
| 评估 | 时间切分、AP、验证阈值、每日预算等 | 时间切分天然保证同一注入洗钱链不跨分区 |

四类事件均以当前交易为锚点：`fan_in` 和 `fan_out` 使用多个不同对手方；`pass_through` 比较当前转出与历史流入；`relay` 当前仅构造时间递增的三笔转账、四个不同账户的中继。币种、金额比例、时间窗和保留历史数影响事件覆盖。它们是可疑行为描述，不是标签判定规则。正常工资发放、商户结算和企业资金调拨也可能产生相似结构。

当前默认时间窗为 24 小时、每个历史桶最多保留 32 条记录，fan-in/out 的最少成员数为 3，部分金额比例约束为 0.8–1.2。这些值是原型配置，不是已验证的金融业务阈值。队列截断后，基础收付统计反映保留下来的历史，不能写成完整 24 小时账户统计。

历史成员的基础特征在其自身到达时计算并保存，不能在形成后续事件时偷偷用更新后的未来历史重算。单笔交易可能参与多个事件，事件也可能共享成员；这种重叠必须在复杂度、解释规模和统计不确定性分析中体现。

### 3.3 当前模型的准确名称

当前 `event` 变体可以称为“角色与时间感知的有界邻接行为事件编码器”（role/time-aware bounded incident-event encoder）。它先编码当前交易和历史成员，再对成员池化形成事件表示，最后汇总事件并分类。这里的结构主要是交易与行为事件的成员关联及成员角色；账户节点并未在一个完整全局异构图上反复传递消息。

事件门控权重不是解释真值。当前解释候选按预定义的事件成员规模排序，不能把其输出叙述为模型已经学会挑出最小洗钱子图。当前训练目标也没有持久同调、证据最小化或删除忠实性约束。

### 3.4 v0.4 的 LLM 接入及实验边界

新增 `compile-detection-rules` 将自然语言编译为 `DetectionPolicy`，仅允许 `fan_in`、`fan_out`、`pass_through` 和固定三笔交易的 `relay`。规则窗口、人数与金额比例实际参与确定性事件构造，不只是生成说明文字。历史容量不足、未知字段或未知算子被拒绝。通用旧 DSL 与该结构独立，不能互换输入。

策略在训练前确定，完整策略和来源写入运行清单及模型 sidecar；checkpoint 保存策略和历史配置摘要。训练、推理及证据删除回放均使用同一冻结策略，不调用 LLM。评价区间不得临时重编译规则、根据测试标签选择规则或改变窗口。结构有效、多个生成一致，不等于领域语义正确；必须对照原文审查数值、单位、遗漏谓词与不支持条件。

如果把 LLM 规则编译作为系统实验，应预先建立人工核对的规则—策略测试集，分别报告：结构有效率、实际调用与修复次数、可表达规则的语义准确率、不可表达规则拒绝率、数字/单位错误率、调用成本及模型版本。语义指标需要独立人工标注，不能直接把 `semantic_agreement` 当正确率。规则集、提示词与生成设置在检测主实验前冻结。LLM 生成与人工配置得到同一策略时，检测结果应一致。

新增 `describe-alerts` 使用 `narrative.py` 构建事实白名单。LLM 选择已存在的事实编号与有限核查枚举，中文事实叙述及强制限制由程序生成；它不自由书写交易事实，不决定洗钱标签，不修改模型分数。事实引用校验只证明引用在输入中存在，不证明源记录真实或审计充分。报告只覆盖输入中前 N 笔已审计目标，明确记录遗漏数量，不能声称覆盖全部告警或实现法规 RAG。

报告实验可以评价事实引用有效率、无依据事实拒绝率、限制保留率、报告覆盖、人工可用性、延迟与成本。由于事实文本由程序渲染，不能把格式上的零新增事实包装成“LLM 推理正确率 100%”。如检验报告对调查效率的帮助，需要人工任务设计和对照，不可用模型自评代替。

当前配置保留 `deepseek-v4-flash`。2026-10-08 充值后，模型列表鉴权及 JSON 生成成功；四类规则的两次真实编译均有效、参数一致且未修复。该生成策略已用于演示训练与证据回放，三笔交易的真实报告生成成功，接口返回模型名为 `deepseek-flash`。此前 HTTP 402（余额不足）是历史失败。模拟测试和这次真实调用分别验证程序约束与接口闭环，不构成公开数据性能或通用语义正确率证据。实际调用记录请求/返回模型名、token 使用与冻结生成设置；兼容名称的映射以 [DeepSeek 官方模型说明](https://api-docs.deepseek.com/quick_start/pricing/) 为准。

LLM 接口与报告支持工程闭环；目前的投稿方法贡献仍应集中于行为事件表示、检测收益及证据忠实性，不用增加 LLM 模块来替代强基线和真实实验。

### 3.5 可以提出、但尚未证明的贡献

拟贡献应收敛到三个可检验点：

1. 在严格可见历史下，把交易组织为有类型、有角色、有相对时间的局部行为事件，研究该表示相对纯交易统计和扁平图特征是否有增益。
2. 以全候选交易、低正例率和固定调查预算评价检测收益，分析事件覆盖、结构变化与历史截断对收益的影响。
3. 从原始源交易层面重建删除后的历史，评价行为证据对模型输出的实际影响，并与相同删除规模的随机控制比较。

实现这三点仍不自动构成新颖性。需要和近期 AML 图特征、时序图检测、行为模式表示及图解释研究逐项比较；如果现有方法已覆盖同一机制，要调整方法问题或诚实定位为实证研究。题目和摘要应在完成强基线与消融之后确定。

## 4. 可检验研究问题与假设

| 编号 | 问题与假设 | 主要比较 | 支持该假设所需证据 | 反例与失败解释 |
| --- | --- | --- | --- | --- |
| H1 | 保留行为事件的成员组织，比同信息的扁平特征更有助于识别 | `event` 对 `flat`、参数规模对齐模型、GFP + LightGBM | 同切分多种子 AP 与预算召回增益；按事件覆盖分层仍成立 | 增益仅来自参数更多，或仅来自规则筛选的少数正例 |
| H2 | 事件内角色、类型、相对时间具有额外作用 | `event` 对 `no_role`、`no_time`、`untyped_event` | 消融差异在多个种子和时间区间重复；角色置乱也有一致影响 | 各消融几乎无差异；表示主要依赖基础金额和账户统计 |
| H3 | 行为证据对模型分数的影响超过等规模随机历史删除 | 源交易删除与匹配随机删除 | 删除差值的区间估计、正负方向、覆盖率和规模分层 | 随机删除效果相同，或证据删除提高风险分数 |
| H4 | 结构收益在低正例率与不同生成配置下仍有一定稳定性 | HI 内时间测试、LI 内时间测试、HI → LI 冻结迁移 | 不重调目标域阈值时报告 AP、预算召回及告警负担 | 仅在 HI 有效；迁移后基线优势消失或误报上升 |
| H5 | 有界事件处理存在有意义的精度与资源权衡 | 时间窗、历史数、事件数与相应性能和资源曲线 | 明确硬件及计时边界；收益与成本成对报告 | 加大窗口只能增加成本；事件审计成本不适合目标预算 |

AP 与固定预算召回为预先约定的主要观察量，不用单次 F1 最优结果替代全部判断。显著性与实际意义分开报告；在看到测试结果前，与导师约定实际有用的最小收益以及可接受的计算成本。不能先看结果再挑一个最有利指标当主指标。

H2 的 `no_time` 目前只去除事件成员的相对时间与事件跨度输入。基础交易的小时特征仍存在，事件构造仍使用时间窗，因此它检验“事件编码中的时间信息”，不能称为完全无时间模型。`untyped_event` 去除事件层类型、角色、时间与描述量后，仍保留成员分组与成员内容，也不等于纯交易基线。

## 5. 公开数据方案与标签边界

### 5.1 主数据：IBM AML

IBM 官方数据由多智能体虚拟世界生成，全部为合成记录，不是银行真实数据的匿名化版本。其公开数据适合可复现的有监督交易检测，但模型可能学习到生成器特征。参见 [IBM AML-Data 官方仓库](https://github.com/IBM/AML-Data)、[官方 Kaggle 数据入口](https://www.kaggle.com/datasets/ealtman2019/ibm-transactions-for-anti-money-laundering-aml) 与 [NeurIPS 2023 原始数据论文](https://arxiv.org/abs/2306.16424)。

优先按以下顺序开展实验：

1. HI-Small：检查数据适配、因果构建、强基线与方法消融，先确定问题是否成立。
2. LI-Small：在较低洗钱发生比例下独立训练与时间测试，检查告警预算效果。
3. HI → LI：冻结 HI 训练模型及预处理，在 LI 上按预先声明的启动政策回放；不能使用 LI 测试标签重调阈值。
4. 有资源时增加中等规模数据，检查结论能否在规模变化下重复；不能用多跑几个数据名称代替独立数据来源。

HI 与 LI 属于同一生成框架的不同配置，不是两个独立银行来源。HI → LI 应称为同生成框架下的配置迁移或发生率变化测试，不称为真实跨银行外部验证。若加入 AMLSim，只能称为不同合成生成器间验证。Elliptic 等区块链数据的实体、标签与交易语义不同，需另定义任务，不能直接拼入同一总体准确率。

### 5.2 标签的唯一入口

当前交易级标签保存在 `case.metadata.evaluation_labels`，按事件 ID 与样本关联。模型与事件构造只读取无标签字段；标签用于训练目标、验证选择和测试评价。数据适配时要记录原列名、0/1 映射、缺失处理和来源文件校验值。

`Is Laundering` 不能作为特征，也不能用于决定某笔交易属于 `fan_in`、`relay` 等事件。注入模式名称和 pattern ID 仅允许进入独立审计表。不能把“属于生成器注入链”自动当作某个人工事件的解释真值；只有数据说明明确提供这种对应且映射审核完成后，才能另行计算结构覆盖指标。

公开数据的负例标签来自生成器的业务设定，不是每条现实交易都经过人工排除洗钱。论文可以评价相对该数据标签的检测性能，不能外推为已达到银行实务鉴定能力。

### 5.3 数据审计清单

每个正式运行至少记录以下内容：文件名称与 SHA-256、发布版本或下载日期、许可、总行数、解析后的候选数、正例数与比例、时间范围、账户数、币种与支付方式、缺失值、重复行、时间戳精度、同时间戳比例，以及排除记录的具体原因。

核查金额支付列与收取列、付款币种与收款币种的对应。跨币种不能直接按数值金额判断资金守恒，当前币种分桶与比例规则不能被描述为完成了外汇换算。若以后引入汇率，要确保汇率在交易时可得并独立说明数据来源。

IBM 仓库代码许可与实际数据许可不同；官方仓库说明数据使用 CDLA-Sharing-1.0。发布实验包时保存数据获取说明、处理代码和必要校验值，并按数据许可处理衍生数据，不能仅沿用代码的 Apache-2.0 说明。

v0.5 的 `audit-data` 可以记录源文件校验值、候选与账户数量、标签覆盖和比例、币种/渠道、金额、时间范围、同时间戳比例、原文件逆序及业务字段重复。它保留重复记录，不把未标注记录补成负例，也不把标签送入构图。严格 CSV 读取仍会拒绝非法行。审计本身不验证文件真实性、上游发布版本、数据许可或链归属，这些项目应与下载来源记录及辅助模式文件人工核对。`--limit` 是原始文件前缀，不是随机样本或完整时间范围；源校验值与读取行数必须同时报告。

## 6. 时间切分、注入链审计与实验冻结

### 6.1 主切分

默认按时间顺序约 60% / 20% / 20% 分为训练、验证和测试。以完整相同时间戳组作为边界单位，比例只是目标值；实际记录数量可能有所偏离。保存各区间首末时间、样本 ID、类别计数和比例。三个区间均须非空，训练与验证均须包含正负类别；验证只有一个类别时拒绝选阈值，不以随机切分补救。

归一化、类别权重、模型参数仅在训练区间拟合。窗口、历史上限、事件比例参数和模型超参数通过训练与验证确定。阈值仅由验证区间选择，测试集只用于最终评估。使用多个测试时间切分或滚动窗口时，要预先冻结窗口和模型选择规则。

不能以“先对全文件建立完整交易图，再按交易时间划分标签”的方式满足因果要求。完整历史回放是允许的，但每个样本的邻居、统计与事件必须只含其当时可见记录。外部基线同样受此政策约束。

### 6.2 时间切分不保证链隔离

同一注入洗钱链可能持续多个时间段，其早期交易处于训练区间，后续交易处于测试区间。账户也可能重复出现。因此，严格时间切分保证没有未来信息泄漏，**不保证 pattern-disjoint、chain-disjoint 或 account-disjoint**。

若数据提供可验证的 pattern ID，应另做独立审计：统计每个注入链出现于哪些区间、跨区间链比例，以及测试中“训练曾见链”和“训练未见链”的表现。pattern ID 不进入特征、事件构造或模型选择。若标签辅助文件无法可靠映射交易，写明“链隔离无法核实”，不要声称已满足。

链隔离和账户隔离可以作为额外困难测试，但不能通过把未来同链记录搬到训练区间破坏时间顺序。可选择后期完整新链作为附加测试，或在预先定义的留出政策下删除跨界链，并公布因此改变的候选规模与发生率。这个结果与全交易主测试分别呈现。

### 6.3 冻结与复现

第一次正式测试前保存协议版本、数据校验值、切分 ID、规则配置、模型配置、选择标准和随机种子。看到测试结果后新增实验，必须标为探索性；新方法定型后应使用另一个未参与迭代的时间区间验证。不要把反复测试后得到的最优配置仍称为一次独立测试。

`manifest.json`、`splits.json`、模型、预测表与评价结果应互相对应。源文件路径本身不足以复现，要同时保存校验值、依赖版本和代码提交号。当前运行清单是这一工作的起点，完整复现包仍需正式数据和外部基线记录。

### 6.4 v0.5 多种子运行的实际口径

`detect-benchmark` 一次构造因果样本及时间切分，多个种子和模型共用相同候选 ID。训练只接受训练段样本和标签；每个模型的阈值只由验证段选择，测试段不会触发参数调整或 LLM 调用。输出目录必须新建或为空；`benchmark_manifest.json` 保存来源、配置、策略、依赖、划分、用途及完成/失败状态，各种子保留独立模型、指标和预测，根目录导出可读表格与 JSON/CSV。

汇总使用有效值的均值与样本标准差（ddof=1），缺失指标保留缺失；有效值只有一个时不报告标准差。`event` 与控制模型的差值按共同种子配对，预算项按实际比例匹配。多个优化种子共用同一测试段，因此这些标准差不是独立数据集上的置信区间，更不是显著性结论。后续仍需预先约定的多个时间区间，以及尊重账户/资金链依赖的重抽样设计。

`data-role=smoke/pilot/public_dataset_run` 是用途声明，程序不会凭该字段证明数据真实或满足投稿条件。固定前缀上成功运行仍属于先导验证。默认 benchmark 不运行昂贵删除审计；在冻结评价计划后，用 `detect-score` 恢复选定模型单独生成解释。树模型需保存原生 `.txt`、配置 `.json` 与检测设置 `.settings.json` 三个文件。版本记录还应补充硬件和原生库构建选项；本机无 OpenMP LightGBM 的速度不代表多线程实现。

## 7. 基线与消融：两类证据分开

### 7.1 基础学习对照与必做外部基线

| 基线 | 为什么必须做 | 公平比较要求 |
| --- | --- | --- |
| LightGBM：基础交易与因果账户统计；v0.5 已实现 | 判断深度模型是否优于强表格分类器 | 相同候选、历史可见性、切分；正式实验补齐验证调参预算 |
| GFP + LightGBM | 图模式特征与树模型本身已有较强 AML 结果，必须排除“只是规则统计有效” | 使用作者实现或可审核复现；明确图特征、时间窗、未来信息检查和实现差异 |
| Multi-GNN，至少复现一种适用于有向多重图的强配置 | 判断局部事件方法相对专用 AML 图模型的价值 | 不直接搬用论文分数；在本协议切分上重跑，保留重复边、方向与公平历史政策 |
| 参数规模对齐的 MLP | 排除当前 `event` 相对 `base`/`flat` 的参数与容量差异 | 报告参数数、调参次数及训练时间，不只令隐藏维度相同 |

GFP 原始工作研究流式子图模式特征与梯度提升分类器，可作为结构特征方面的直接竞争方法；本文不复述其论文指标作为本项目结果。参见 [GFP 原始论文](https://arxiv.org/abs/2402.08593) 和 [ICAIF 2024 论文 DOI](https://doi.org/10.1145/3677052.3698674)。

IBM 的 Multi-GNN 官方仓库包含 GIN、GAT、PNA、RGCN 及面向有向多重图的适配。应核查反向消息、边更新、端口等配置，并依据验证结果选择强配置。参见 [IBM Multi-GNN 官方代码](https://github.com/IBM/Multi-GNN)。若作者原始训练协议允许完整静态图，而本文要求到达时历史，则需分别呈现原协议复现与因果适配结果，说明信息条件差异；不能将完整未来图基线与因果方法混为相同任务。

外部基线尚未跑通时，结果表明确写“未完成”，不能留一个没有来源的数字，也不能把内部对照称为已经超越 AML 主流方法。若基线适配失败，记录失败原因、资源限制和已尝试配置，不能因此省略强基线后直接宣称优势。

当前 `lgbm_base` 使用 24 个基础特征，`lgbm_flat` 追加与神经 `flat` 相同的 16 个事件摘要，不读取事件成员向量、角色或身份编号。树模型的基础 scaler 只拟合训练段当前交易，神经模型因共享成员编码而同时使用训练时可见成员；两者均不得拟合验证/测试统计。树模型类别权重为 N/(2×Nclass)，与神经正类权重具有相同正负比例。默认树参数、神经参数不代表容量或调参预算已对齐，需要分别在验证段审查；所有测试比较不得根据结果重新挑选超参数。当前树模型没有随机行列采样且固定单线程，不同种子得到相同分数是合理现象。原生接口参见 [LightGBM 官方 Python 文档](https://lightgbm.readthedocs.io/en/stable/Python-Intro.html)。

### 7.2 当前内部对照

| 变体 | 输入与结构 | 可用于回答的问题 |
| --- | --- | --- |
| `base` | 基础交易及有界账户历史统计 | 增加行为事件后是否有收益 |
| `flat` | 在基础表示上加入事件类型对应的计数、成员数、跨度和比例摘要 | 成员组织是否比事件摘要更有效 |
| `event` | 成员内容、角色、类型、相对时间与描述量，按事件组织并汇总 | 当前完整原型的表现 |
| `no_role` | 事件层角色嵌入置零 | 角色输入的增益 |
| `no_time` | 事件层相对时间与跨度置零 | 事件编码层时间输入的增益，非全系统无时间 |
| `untyped_event` | 事件层类型、角色、时间和描述量置零，保留成员分组 | 事件语义相对单纯成员分组的增益 |

这些是内部消融，不是独立领域基线。`no_role`/`no_time`/`untyped_event` 尽量保留相同张量维度，帮助控制结构消融的容量差异；`base`/`flat` 与 `event` 的参数量仍可能不同，要增加容量对齐实验。

建议额外加入成员角色置乱、事件分组置乱、事件类型置乱三种控制。置乱只能在当前可见样本范围内执行，不引入未来记录；不能根据测试标签决定置乱方式。若置乱后性能基本不变，就应质疑“结构感知”叙述。

## 8. 评价口径

### 8.1 Average Precision 的准确术语

主排序指标采用 Average Precision（AP）。将分数从高到低排序，同分样本作为一组同时进入；每组正例带来的召回增量乘以该组进入后的 precision，再求和：

```text
AP = Σ_g (R_g − R_(g−1)) × P_g
```

这里是分段式 AP，不是通过梯形积分得到的 PR 曲线面积。论文表头写 `AP`，实现与图表说明明确同分处理；不能为了名称显得熟悉而把它改叫梯形 PR-AUC。若另行计算 trapezoidal PR-AUC，要单独列指标与实现，两者可能不同。

正例比例是必要参照；AP 随发生率和候选构成变化，不能把 HI 与 LI 的 AP 差异全部归因于模型泛化。没有正例时 AP 与 recall 无定义，输出 `null` 并公布正例数，不能当作 0 分或删除该区间而不解释。

### 8.2 固定阈值指标

阈值通过验证集最大 F1 选择；同 F1 时偏向较高阈值以减少告警。选择过程需要验证集同时有两个类别，允许保存大于 1 的“全部不告警”阈值。测试集使用冻结阈值，报告 precision、recall、F1、TP、FP、TN、FN、正例比例和每 1,000 笔候选交易的误报数。

`false_positives_per_1000 = 1000 × FP / N`。这里分母为全部候选交易，不能称为 `1000 × FPR`，后者分母是负例数。无告警时 precision 按当前软件口径记 0 并列出告警数；无正例时 recall/AP/F1 记 `null`。正文说明这些边界约定。

验证集最大 F1 只是当前可复现的阈值策略，未必是银行的最佳运营阈值。若改用验证集误报约束、成本或预算选择，先定义再跑测试，并与原策略分开报告。

### 8.3 UTC 每日固定调查预算

对测试集中 UTC 日期 d 的全部候选交易，令 N_d 为候选数，预算比例 q ∈ {0.001, 0.005, 0.01}。预算定义为：

```text
B_d = floor(q × N_d)
```

按风险分数降序排序，同分按 `event_id` 确定顺序，选前 B_d 笔。B_d = 0 时当天不产生调查告警，不强行至少选一笔。每个日期都保留在结果中，包含零预算日、候选数、正例数、选中 ID、告警数、TP、FP 与召回。

总体预算指标按实际选中记录汇总：调查告警总量 ΣB_d、precision、recall、FP、每千笔候选误报数，以及逐日列表。主要采用总体 micro recall，即全部捕获正例除以全部正例。若另报日均 recall，必须说明无正例日如何处理；不能静默删除这些日期制造更好结果。

这一政策对完整一天的分数做事后 top-B 排序，是**按日离线预算评价**。单笔分数仍满足因果输入，但选择谁进入当天预算依赖完整候选集合与一天总量，不能称为已经实现实时预算分配。真正在线调查分配需要另行定义预算到账、剩余配额和到达顺序策略。

### 8.4 不确定性与配对比较

正式主实验至少采用 3 个、尽量 5 个预先固定的训练随机种子；所有方法共享同一数据切分和候选集。报告每个种子、均值与离散程度，而不是只报告最好种子。多次重复应覆盖模型训练随机性，不能重复读取同一预测文件冒充独立实验。

交易与事件存在账户、时间和成员重叠，不能默认每笔交易独立同分布。置信区间优先采用按日期的配对块重采样；若可用的日期少或注入链跨天，应进一步报告时间块或 pattern ID 审计及敏感性。方法比较在同一次重采样中使用相同块，报告 AP 差值和预算召回差值。仅有一个合成生成器时，区间也不代表对所有银行的泛化范围。

## 9. 证据忠实性协议

### 9.1 必须删源交易，再重建整个可见前缀

给定目标交易 x_i，前缀 P_i 包含时间严格早于 t_i 的全部可见交易与 x_i 本身，不含其他同时交易或未来记录。候选证据 E_i 为行为事件关联的历史源交易 ID 集合；目标交易本身不删除。

删除实验必须执行以下步骤：

1. 冻结训练后的模型、归一化、阈值和事件构造配置。
2. 从 P_i 中删除 E_i 对应的原始交易记录。
3. 从头回放剩余的完整前缀，重算账户统计、历史成员特征与事件。
4. 对同一个目标交易重新评分，得到 s_i^−；记录 Δ_i = s_i − s_i^−。

只在最后的事件张量里置零、仅删一条事件关联，或保留删除前计算出的历史统计，都不能替代该协议，因为同一源交易可能影响多个统计量和多个事件。共享成员按唯一源交易去重后计入删除规模。

删除量 Δ_i 可以为负，必须保留。证据删除后风险升高说明该证据可能是抑制性输入、模型不稳定或候选解释不忠实，不能把负值截断成零或只发表成功案例。

### 9.2 等规模随机删除控制

对每个 E_i，从同一可见前缀的历史交易中随机选择相同数量的唯一源交易，并按相同重建步骤计算 Δ_i^rand。随机控制不能删除当前交易，不能从未来抽样，不能依据洗钱标签挑选。固定并保存抽样种子。

当前原型每个候选执行一次等规模随机删除，只适合检查审计机制能运行。正式研究至少对每个候选执行 20 次随机控制；同时设置与证据在时间距离、币种及相关端点接近的分层匹配控制。否则随机删除很可能落在无关账户上，过弱的控制会夸大行为证据的特异性。匹配政策须事先冻结，无法匹配时报告数量和回退策略。

报告 `Δ_i − mean(Δ_i^rand)` 的分布与区间，同时报告证据删除量和随机删除量本身。按证据规模、事件类型、原始风险区间、预测正确与否分层。说明解释覆盖率、无事件比例、每条证据平均源交易数和重建计算成本。

当前候选按成员规模等确定性规则限制为有限个事件，并不是穷举所有子图。不能把“若干候选中分数下降最多的一个”声称为全局最小充分解释。若根据删除效果选择最佳候选，必须公布候选数、选择规则及所有候选结果，避免只保留最大下降值带来的选择偏差。

### 9.3 只保留证据的试验仅算审计

可以另外保留目标交易与 E_i，删除前缀中的其他交易，再重建并评分，称为 `evidence-only` 保留审计。它描述在一个经过大幅修改的输入环境中模型是否仍给高分，不是对现实世界证据充分性的证明，也不代表完整业务上下文下的因果机制。

源交易删除同样可能产生分布外输入，因此“分数下降”属于模型依赖与忠实性证据，不等于证明这些交易导致了洗钱。若要提出因果解释，需要更强的数据生成、干预假设与独立实验设计。

### 9.4 审计呈现

每条展示证据必须回查：源文件或记录 ID、付款与收款账户、交易时间、金额与币种、事件类型、成员角色和相对时间。账户、交易、行为事件可以作为证据图节点，关联保留角色。展示时区、金额单位和脱敏规则要统一。

论文同时展示成功与失败案例，包括正常业务形成相同形状的误报、未匹配事件的漏报、删除后分数不降的候选。语言模型如用于整理说明，只能改写已验证字段，不能补写犯罪动机或把风险分数转换成“已经洗钱”的结论。

## 10. 效率与规模验证

效率实验分别记录输入解析、因果特征与事件构建、训练、模型推断、输出写入和证据重建时间。公布 CPU/GPU、内存、线程、批大小、模型参数数、交易规模及账户规模。同一阶段的计时边界在各方法间保持一致。

当前 runner 的回放吞吐覆盖输入加载、特征构造与模型推断，排除训练、输出写入和证据审计；单交易 p95 为有限样本上的模型调用延迟，不包括解析与事件构造。这些原型输出不能直接写成生产系统端到端 SLA。对小数据打印的峰值内存也不能证明大规模数据成本。

每个历史桶最多保留 M 条记录，不意味着总内存为 O(M)：活跃桶的数量随账户、币种、方向及窗口增长，完整同时间戳组和事件批次也有成本。旧内存路径仍加载完整输入；v0.6 磁盘路径避免同时保留全部交易与样本，但原生 LightGBM 仍创建内存分箱与权重。正式实验至少画出交易数/账户数对运行时间和峰值内存的曲线，并检查历史上限 M 与窗口 W 的精度成本权衡。

### 10.1 磁盘实验必须额外冻结的协议

1. 数据准备保存完整源文件 SHA-256、实际行前缀限制、半开时间范围和原始来源行号。完整严格读取不代替业务重复与注入链归属审计。
2. 缓存保存数据选择范围、策略与编译来源、保留历史配置、特征顺序、实现摘要及完整时间组切分。构造特征只读取无标签流，独立标签表仅用于训练目标或评价；当前 cache 的 `after` 排除更早上下文，历史从空状态开始，不能称为带预热评价。
3. 神经模型首遍仅训练段拟合 scaler 和权重，后续每轮重读训练段并核对输入指纹；训练默认源顺序或固定种子的有界批次打乱。它与旧全局排列算法不同，论文公布缓冲大小和批大小，不能把运行顺序差异写成方法收益。
   `fixed_periodic` 仅按特征定义将周期正弦/余弦保持在天然范围，其余列使用训练统计；不引入验证/测试统计。该选项针对短训练时间覆盖的数值风险，预处理策略随模型冻结。先导窗口已有结果暴露，在此窗口重跑只作为探索，不升级为正式测试。
4. LightGBM 只读训练段磁盘矩阵；当前和历史成员的 scaler 范围按各模型定义公布，不用验证/测试统计。磁盘输入不保证原生训练常数内存。
5. 每个模型只以验证分数选择阈值，并在模型训练配置与配套设置中保存绑定。恢复评分不重新选择阈值。兼容输入定义的新缓存可作迁移输入，同时保留训练缓存与当前缓存的各自摘要。
6. 磁盘 AP 与每日预算使用全候选排序，不按事件筛选。每日选中 ID 的展示最多1,000个，但全部统计精确计算，省略数量与全部预测单独保留；不能把展示截断误当预算截断。
7. 缓存评分计时包含缓存解码、模型、可选来源查询和分数写盘，排除特征构造与指标；训练计时包含输入读取和 scaler 拟合。与旧回放吞吐计时边界不同，分别报告，不直接计算加速比。
8. 清单区分完成、失败和中断；部分模型输出不能当作完整实验。新缓存告警标记未做解释审计，解释结果必须另行使用源交易重建协议产生。

本轮完整环境362项测试通过，标准库环境275项通过、87项可选运行时测试跳过。软件测试用于验证上述边界，不能据此证明检测有效性；公开先导结果、输入摘要与恢复核验见 `docs/experiment_progress.md` 和本机 `outputs/v06_verification.json`。

解释会反复回放目标交易的历史前缀，可能远比一次打分昂贵。分别报告全候选检测吞吐与有限告警的解释审计成本；若仅解释 top-k，就明确 k、选取政策和被解释比例。

## 12. 没有明显增益时如何处理

1. **先审计信息与公平性。** 确认外部基线和本方法看见相同历史，候选未过滤，归一化与阈值未用测试标签，ID 或模式标签未进入表示。修复协议问题后重跑，不以解释性叙述掩盖检测结果。
2. **判断事件是否覆盖目标。** 分别统计无事件、各事件类型、截断前后及正负例覆盖。若大多数正例根本不产生事件，问题可能是表示覆盖不足；若正常结算大量匹配，问题可能是语义缺乏区分。
3. **区分结构与统计收益。** `flat` 或 GFP 表现同样好，说明当前池化结构未提供额外信息；角色置乱无影响，则角色语义主张缺乏支持。保留这一发现，不把小幅随机波动称为突破。
4. **检查时间与配置依赖。** 只在 HI、某一时间段或某一个窗口有效，就限定结论，讨论发生率、账户活动和生成器结构。不给 HI/LI 同源结果冠以真实银行泛化。
5. **分析性能与成本的取舍。** 检测精度接近强基线而审计更可追溯、资源更低，可能形成较窄的工程研究问题，但这些优势也要量化。解释更好不能自动抵消检测下降，需要明确目标与约束。
6. **必要时调整论文贡献。** 可研究行为事件在哪些条件下有效、哪些反洗钱图特征是冗余的，或因果评价如何改变常见结论。是否达到 KAIS 的原创性与证据要求仍需导师与相关工作评估；失败分析有价值，但不保证单独可发表。

不能通过减少负例、只评价规则命中的交易、增加测试集调参、挑最好种子、去掉零预算日或只展示解释成功案例制造增益。若年底尚未形成可靠证据，提交诚实可复现的阶段成果比宣称原型已经完成论文验证更有用。

## 13. 投稿前证据门槛与论文结构

最低证据门槛：公开数据与许可说明完成；标签与未来信息审计通过；GFP + LightGBM、Multi-GNN 等强基线在本任务重跑；内部消融与容量控制完成；AP、固定阈值与预算指标口径一致；多种子与不确定性报告完成；源交易删除有多次等规模及匹配随机控制；效率计时边界透明；失败案例与同源合成数据局限明确；至少一次独立复跑能还原主要结果。

论文可按以下结构组织：

1. 引言：交易到达时的信息限制、低正例率与调查预算、行为证据需求，以及现有方法尚未解决的具体问题。
2. 相关工作：AML 图特征与图模型、时间约束、行为事件表示、图解释；用机制差异表支撑定位。
3. 问题定义：候选集合、可见前缀、标签粒度、行为事件和预算，不依靠平台描述代替定义。
4. 方法：事件构建约束、成员与事件编码、复杂度与边界；只写已实现的最终机制。
5. 实验：数据、强基线、公平信息政策、切分、选择标准、主结果与消融。
6. 忠实性与效率：源交易重建删除、随机控制、资源曲线与真实失败案例。
7. 局限与结论：合成同源、注入链可能跨区间、有界历史、解释干预边界，以及下一步研究。

投稿标题可暂用“面向因果交易流的行为事件表示与可审计反洗钱检测”，最终英文题名应根据真正得到支持的贡献修改。不要提前使用“首个”“最优”“因果解释”“完整异构图学习”或“已部署银行”等未经证据支持的表述。
